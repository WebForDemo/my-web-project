Hermes CLI 操作手冊

Hermes 有兩套指令介面——終端機的 hermes … 和聊天裡的 /…， 兩者不通用，這是新手最常卡住的地方。本手冊的指令清單直接取自本機安裝的版本， 不是複製文件。

兩套介面，不要搞混

同一個功能在兩邊可能都有，但能做的事不一樣。這是整個 Hermes 最容易卡住的地方。

最常見的錯誤

在聊天裡打 /model 想新增一個供應商，卻發現清單裡沒有想要的。 因為 /model 只能在已經設定過的項目之間切換。 要新增，必須 /quit 退出，在終端機執行 hermes model。

第一次使用的四個步驟

  1. 跑一次設定精靈

    $ hermes setup

    會依序帶你走過模型、工具、終端機後端等設定。也可以只設某一段：hermes setup model、hermes setup tools、hermes setup gateway。

  2. 選模型與供應商

    $ hermes model

    互動選單，會把 provider、base_url、model 三項一次接好。只改其中一項容易留下半套設定。

  3. 確認環境沒問題

    $ hermes doctor

    檢查依賴、憑證、各供應商的連線健康度。裝完或出狀況時第一個該跑的指令。

  4. 開始對話

    $ hermes                          # 互動模式
$ hermes chat -q "一句話問題"      # 單次提問，問完就結束

    注意：-q 每次都是全新 process，會重新承擔啟動成本。連續提問請用互動模式。

設定寫在哪、誰讀得到

Hermes 有兩個設定來源，而它們不是可以互換的。搞錯會出現「設定成功但完全沒作用」。

實際踩過的坑

設定 LINE 白名單時用 hermes config set LINE_ALLOWED_USERS …， hermes config get 讀得回值，但 gateway 持續拒絕訊息。 原因是 plugins/platforms/line/adapter.py 用的是 os.getenv("LINE_ALLOWED_USERS", "")。

判斷原則：凡是全大寫、底線分隔的平台變數（LINE_*、TELEGRAM_*、 DISCORD_*），一律寫進 .env。

怎麼寫進 .env

# 新增一項
$ echo 'LINE_ALLOWED_USERS=U1234…' >> ~/.hermes/.env

# 確認寫進去了
$ grep "^LINE_ALLOWED_USERS" ~/.hermes/.env

# 讓執行中的對話重新載入（不必重啟）
> /reload

整包備份最省事

hermes backup 會把整個家目錄打包成 zip，hermes import 還原。 不必自己判斷該收哪些檔案。但備份檔內含金鑰與憑證，請當作機密保管。

出狀況時的順序

由淺入深，大部分問題在前兩步就能定位。

  1. 先健檢

    $ hermes doctor
$ hermes status

    檢查依賴、憑證、各供應商連線。九成的設定問題這裡就會現形。

  2. 看日誌

    $ hermes logs
$ tail -f ~/.hermes/logs/gateway.log     # 訊息平台問題看這個

    Gateway 的 log 會逐筆記錄 inbound message → response ready → Sending response，可精確定位斷在哪一段。

  3. 確認認證還在

    $ hermes auth list
$ hermes auth status <provider>

  4. 還是不行就打包求助

    $ hermes dump      # 產生可分享的設定摘要
$ hermes debug     # 上傳日誌與系統資訊

    注意：分享這些輸出前先確認沒有夾帶金鑰。

常見狀況

症狀成因與解法
設定了卻沒作用 平台變數寫錯地方。改寫進 ~/.hermes/.env，見「設定與檔案」
/model 找不到想要的模型 該供應商還沒設定過。/quit 退出後在終端機執行 hermes model
重啟後訊息全部沒反應 埠號尚未釋放（address already in use），Hermes 會在 30 秒後自動重試。等約 40 秒再測
回應很慢 看日誌的 api_calls。大於 1 代表 agent 動用了工具。用 /tools 關閉不需要的工具最有效
首次執行特別慢 冷啟動成本，屬正常。hermes chat -q 每次都是新 process，連續提問請用互動模式
找不到 hermes 指令 PATH 未生效。macOS 的 Terminal 讀 ~/.bash_profile 而非 ~/.bashrc
更新後壞掉 本機修改可能被覆蓋。檢查 cd ~/.hermes/hermes-agent && git status
想緊急全部停下 hermes pause 立即暫停 cron、kanban 與新的閘道回合；hermes resume 恢復

安全相關

開放給他人使用前

Hermes 預設帶終端機執行與檔案讀寫工具。若要把它接上訊息平台給別人用， 先以 hermes tools 關閉不需要的工具，並用 hermes pairing 或平台白名單控制誰能對話。

另外 /yolo 會跳過所有危險指令的核准——單機自用時很方便， 但在開放環境等於拆掉最後一道防線。 

# 供應鏈稽核：檢查 venv、外掛、MCP 伺服器的已知漏洞
$ hermes security

# 從歷史核准紀錄產生允許清單建議
$ hermes approvals
