01 — 資料怎麼流動

連線架構

從 ChatGPT 到 TIPTOP 資料表的完整路徑。服務拆成內外兩個行程： 對外只開放兩項唯讀查詢並要求金鑰，內部介面只綁 localhost、完全不觸網。

每一段連線

路段協定 / 埠驗證狀態
ChatGPT → OpenAIHTTPS OpenAI 帳號已驗證
OpenAI → Cloudflare 隧道HTTPS :443 無（網址即入口）已驗證
隧道 → 對外行程HTTP :8081 X-API-Key 標頭已驗證
瀏覽器 → 內部行程HTTP :8080 僅 localhost 無（不對外）已驗證
核心 → TIPTOP GatewaySOAP / XML :6384 XML 內 <Authentication>已驗證
核心 → OracleOracle TNS :1521 帳號密碼停用

一次查詢的六個步驟

1判斷

模型依 OpenAPI 的描述決定要不要呼叫，並自行帶入 keyword 與 limit。

2驗證

對外行程檢查 X-API-Key。錯誤或缺少一律回 401 並寫入日誌。

3組封包

讀取 SOAP 範本，改寫營運中心與查詢條件。範本與原版逐位元組相同。

4呼叫 ERP

送到 TIPTOP Gateway，由 4GL 服務查詢對應資料表後回傳 XML。

5轉譯

解析 <Record>，把 geb02 這類代號換成「國別名稱」。

6回傳

附上總筆數與截斷旗標，讓模型知道結果是否完整。實測往返約 41 毫秒。

02 — 模型負責哪一段

語言模型的位置

加上語言模型後改變的不是資料，而是「人要懂多少才能取得資料」。 模型負責意圖與表達，工程負責契約與權限，ERP 仍是唯一的真相來源。

模型改變了什麼、沒改變什麼

面向 原本的做法 加上語言模型之後
使用者要具備的知識 要知道 azi04 是「金額小數位數」，也要知道該開哪個畫面 用中文問就好，欄位代號由系統對照
查詢條件 操作表單、下拉選單、勾選欄位 模型自行推導 keyword 與 limit
跨筆比較 匯出 Excel 自己比對 直接問差異，模型對齊欄位後回答
新增一種查詢 設計畫面、寫前端、測試、教育訓練 加一個端點與一段文字描述
資料由誰保證ERPERP，完全不變
權限由誰控管ERP 與應用程式 工程護欄，模型無權放寬

為什麼護欄不能省 —— 本次實測

未接動作指令與動作尚未設定時

問「台灣的國別代碼是什麼？」，模型答「TW」，語氣是「根據 TIPTOP ERP 國別檔」。

09:58 最後一筆請求（401） 10:02 使用者提問 10:02 伺服器端無任何請求紀錄

答案來自常識推測，剛好正確。它說不出 TAIWAN 台灣 這個全名，也給不出區域碼 1000。

已接動作補上指令與 API 金鑰之後

問「有哪些幣別？」，模型呼叫動作後回傳完整表格。

10:07:19 172.204.96.41 GET /gpt/currencies?limit=200 200 OK GetCurrencyData 總數=7 符合=7 回傳=7 41ms

7 筆 × 8 欄共 56 個值與 ERP 逐格一致，包含新台幣「1 除匯率」為 0 這種猜不到的設定。

同一個模型，差別只在架構。沒有動作與指令時它會用常識補答案，而且看起來合理 —— 這是最難察覺的失效模式。

所以價值不在「接上模型」，在於接上之後仍然守得住邊界。模型負責理解與表達，資料正確性、權限與稽核一律留在模型之外。

04 — 現況邊界

限制與待辦

目前是可運作的原型，不是可交付的服務。以下每一項都必須在擴大使用前處理。

三個行程都不能關。對外行程、Cloudflare 隧道、這台主機，任一停止 ChatGPT 就查不到資料。內部介面（:8080）可以關，不影響。

隧道網址是隨機且暫時的。重啟後會換一組，config.ini 與 GPT 的結構描述都要重新設定。要固定網址需改用具名隧道。

這個 GPT 必須維持「只有我」。金鑰存在 GPT 設定裡並代表擁有者呼叫，一旦公開分享，任何使用者都能查詢公司 ERP。

Gateway 對大查詢會失效。實測 img01 LIKE 'D%' 等會回 Server Error，連續大查詢會使 aws_ttsrv2 持續報錯直到重啟。需在 ERP 端補分頁或筆數上限。

庫存查詢僅開放給網頁介面，未開放給語言模型。單次結果可達數千筆，超出 Action 的回應與逾時限制；擴充前需先加上必填料號前綴與筆數上限。
